## P1 — блокеры чек-листа

### API-01 · Подключить загрузку ингредиентов

Запрос к `https://new-stellarburgers.education-services.ru/api/ingredients` при монтировании `App` (`useEffect` один раз). URL домена — константа в `src/utils`. Обёртки запросов — отдельный файл (`src/utils/burger-api.ts` или `api.ts`): `checkResponse`, проверка `res.ok` / `success`, цепочка с `.catch()`. Мок `src/utils/ingredients.ts` после этого убрать из рендера.

### API-02 · Preloader и ошибка загрузки

Пока запрос идёт — `Preloader` из `@krgaa/react-developer-burger-ui-components`. При ошибке — понятное сообщение в UI, не только `console.error`. `BurgerIngredients` / `BurgerConstructor` рендерить только после успешных данных.

### MOD-01 · Modal + портал

Компонент `src/components/modal`: шапка с заголовком, `CloseIcon`, `children`. Рендер через `createPortal` в `#modals` (добавить узел в `index.html`). Подписка на `Escape` и снятие слушателя — внутри `Modal` (`useEffect` + cleanup). Типы пропсов в том же файле.

### MOD-02 · ModalOverlay без children

Отдельный `src/components/modal-overlay`: только подложка, `onClick` закрывает окно. **Без** `children` — в брифе это явный критерий. Overlay и окно — соседи в портале, не «окно внутри оверлея».

### MOD-03 · IngredientDetails

Содержимое модалки ингредиента: крупное фото (`image_large`), название, КБЖУ (калории / белки / жиры / углеводы) по макету `docs/screens/image_1765450230_1765530631.png`. Данные — конкретный ингредиент с API. Типографика и отступы из UI-kit. Клик по карточке в списке открывает модалку с этим ингредиентом.

### MOD-04 · OrderDetails с тестовыми данными

Содержимое модалки заказа по макету `docs/screens/image_1765450207_1765530616.png`: номер (например `034536`), подпись «идентификатор заказа», `CheckMarkIcon`, тексты «Ваш заказ начали готовить» / «Дождитесь готовности на орбитальной станции». Номер вынести в константу — позже подменится ответом сервера. Кнопка «Оформить заказ» открывает эту модалку.

### MOD-05 · Закрытие модалок

Три способа: крестик, клик по overlay, `Esc`. Состояние открытия держать в `App` (или рядом), колбэки закрытия мемоизировать (`useCallback`), чтобы слушатель в `Modal` не переподписывался зря.

## P2 — вёрстка и UI-kit

### UI-01 · custom-scroll и высота колонок

На списке ингредиентов и на начинках конструктора повесить `custom-scroll`. Высота — от оставшегося viewport (`flex: 1` + `min-height: 0` или `calc(100vh - шапка - заголовок)`), чтобы на разных экранах скроллился контент, а не страница. Сейчас `.main { height: 100% }` при `h1` вне `main` даёт переполнение: шапка + заголовок + колонки по 100vh.

### UI-02 · Скролл только между булками

Чек-лист: крутятся начинки, булки зафиксированы. Сейчас `overflow-y: auto` на всём `.stack` (`max-height: 400px`), вместе с верхней и нижней булкой. Перенести скролл на `.fillings`.

### UI-03 · DragIcon вместо самописного SVG

В `BurgerConstructor` удалить локальный `FillingIcon`. Взять `DragIcon` из UI-библиотеки ([иконки](https://react-burger-ui-components.education-services.ru/?path=/docs/components-icons--docs)). Булки выровнять с начинками (`pl-8` / отступ 32px), чтобы `ConstructorElement` совпадал по левому краю.

### UI-04 · Подписи булок и состав конструктора

По макету текст булок: «… (верх)» / «… (низ)». Демо-состав лучше приблизить к скрину конструктора (булка + несколько начинок, кольца можно дважды), а не выбирать элементы по жёстким именам. После API собирать демо из загруженного массива (первая булка + несколько `sauce`/`main`), чтобы не отвалиться при смене `_id`.

### UI-05 · Табы: активный раздел и скролл

`onClick` у `Tab` сейчас пустой, активен всегда «Булки». Клик по табу должен скроллить к секции; при ручном скролле — подсвечивать ближайший раздел. `Tab` рендерится не как `li`: либо обернуть в `li`, либо убрать `ul` и оставить `div`/`nav`.

### UI-06 · Счётчики на карточках

Сейчас `Counter` только у булок и всегда `1`. Показывать счётчик, если ингредиент есть в конструкторе; для булки — `2` (верх+низ). Остальные карточки без нулевого бейджа.

### UI-07 · Карточка ингредиента как отдельный компонент

Повторяющийся элемент вынести в `IngredientItem` (или `IngredientCard`): фото, цена + `CurrencyIcon`, имя, опциональный `Counter`, `onClick`. Курсор `pointer`. Упростит модалку и типы пропсов.

### UI-08 · Семантика разметки

- `h1` «Соберите бургер» — внутрь `main`.
- Секции конструктора/ингредиентов — `section`, списки — `ul`/`li`.
- В шапке не класть `p` внутрь `a`; для подписи достаточно `span`. Комментарий из стартера («Тут должны быть ссылки…») убрать.
- Неактивные пункты шапки — `text_color_inactive`, иконки `type="secondary"` (как сейчас), активный — `primary`. Сейчас цвет текста задаётся модулем, плюс двойные отступы: `ml-2` на тексте и `margin-left: 1em` в CSS, `ml-10` на ссылке и `gap: 24px` у родителя.

### UI-09 · Футер конструктора по макету

Цена (`text_type_digits-medium` + `CurrencyIcon`) и кнопка крупного размера справа колонки, зазор ~40px. Убрать жёсткие `width: 532px` у начинок и кастомный `transform` нижней булки: у `ConstructorElement` с `type="bottom"` отражение уже есть.

### UI-10 · AppHeader и index.html

Заголовок страницы и `lang="ru"` вместо «Vite + React + TS» / `lang="en"`. Логотип можно обернуть ссылкой на `/`. Узел `#modals` для портала.

## P3 — качество кода спринта 1

### TS-01 · Типы ингредиента и пропсов

`TIngredient.type` сейчас `string` — сузить до `'bun' | 'sauce' | 'main'`. Типы пропсов новых компонентов — в том же файле, перед компонентом. Для модалок удобен `title?: string` (у заказа шапка без текста).

### HOOK-01 · useMemo и useCallback

Чек-лист требует явное использование:

- группировка/фильтрация ингредиентов;
- сумма заказа (булка × 2);
- карта счётчиков;
- обработчики открытия/закрытия модалок и клика по табу.

### CODE-01 · Имена и CSS-модули

В JS — camelCase, без транслита. В модулях смесь `burger_ingredients`, `imageWrap`, `filling_item` — привести к одному стилю (предпочтительно camelCase). Неиспользуемый `public/burger-basket.svg` убрать или перенести в `src/assets/images`, если понадобится для пустого конструктора.

### CODE-02 · README

Заменить стартовый README: что за проект, стек, как запустить (`npm i`, `npm run dev`), ссылка на API. Чек-лист требует наличие файла; ревьюер смотрит и содержание.

### CODE-03 · Тестовые данные заказа

Константа номера и текстов `OrderDetails` в `src/utils` (например `constants.ts` рядом с `BURGER_API_URL`), не внутри JSX.

## P4 — полировка, не блокер ревью

### POLISH-01 · Пустое состояние конструктора

Если после перехода на API демо-начинок нет — заглушка «Перетащите ингредиенты…» не обязательна в спринте 1 (DnD будет позже), но лучше не оставлять дыру между булками.

### POLISH-02 · a11y модалки

`role="dialog"`, `aria-modal`, `aria-labelledby`, возврат фокуса. В чек-листе нет, ревьюеры иногда хвалят.

### POLISH-03 · Не тащить из старого репозитория лишнее

В [прошлой версии](https://github.com/kirillchistov/react-burger) overlay принимал `children`, модалки завязаны на роутер/Redux, в конструкторе считается КБЖУ всего заказа. Для спринта 1 это лишнее и часть этого **противоречит** текущему брифу (overlay без children). Ориентир — макеты и чек-лист этого репозитория, не полный продукт.
